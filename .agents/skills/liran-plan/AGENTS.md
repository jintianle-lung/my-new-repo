# Project Agent Instructions

本文件记录当前仓库对 Codex/AI 的项目级规则。全局规则仍然有效；四档流程、Superpowers、一次确认和发布门禁之间的关系以本文 `Adaptive Workflow Precedence` 为准，其它未明确覆盖的冲突再采用更严格、更安全的规则。

## Adaptive Workflow Precedence

- 本仓库设计和维护的四档流程负责决定目标任务的调查、需求确认、文档、实现和验收深度。用户未指定时由 Codex 自动路由；用户指定档位且未命中安全门禁时采用用户档位；安全门禁只规定最低档位。
- Superpowers 仍是过程框架，但不得绕过四档路由把轻量或标准任务机械扩张成完整 brainstorming、完整 writing-plans、完整文档树和完整分支收尾链路。轻量、标准只使用当前任务真正需要的技能步骤；深度、完整再按影响范围增加调查和计划。所有档位仍必须完成适用的调试、测试和 `verification-before-completion`。
- 用户在四档确认框中选择 Codex 真机测试、页面样式检查或用户自己测试后，该选择就是本轮正式授权。生成的 `/goal` 必须带上选择结果，执行时不得再次询问是否开始、是否继续或使用哪种工具；只有新增高风险操作、超出确认范围、缺少账号权限或外部依赖时才重新确认。
- 用户明确要求全程不参与、全权交给 Codex 或不再确认，且未明确选择“我自己测试”时，进入全权托管模式。用户明确选择“我自己测试”时，该选择优先，不得被托管默认覆盖。需要 Chrome 时先用 `@Chrome`，无法完成则自动切换 `@电脑`；客观阻塞只记录为 `受阻`。
- 需要集中确认时，`request_user_input` 可用就必须实际调用 Codex 原生选择框，工具不可用时才退回文字编号。收到选择结果后的同一轮必须自动生成提示词，不等待用户再说“请给我提示词”；整条可复制提示词只放一个 Markdown 代码块，内部不得嵌套三反引号。
- 四档流程控制目标任务的研发过程，不取消本仓库自身的发布门禁。只要修改 `plan-docs` 形成可发布变更，无论本次开发被判为哪个档位，仍必须完成版本升级、文档更新、全局同步、校验、提交和推送。

## Long-Term Pitfalls Knowledge Base

- 在本项目执行开发、修复、测试、部署、排障或文档结构调整前，必须先读取本 `AGENTS.md`。
- 继续动手前，必须读取 [docs/pitfalls/README.md](docs/pitfalls/README.md)，并按其中索引读取相关模块避坑文件。
- 新发现的坑、复现过的问题、误判原因、验证盲区或部署接线问题，必须在任务收尾前写回 `docs/pitfalls/` 或等价目录。
- 如果任务中断，仍应尽量把已发现但尚未完全提炼的坑记录为“信息不全，待人工补充”。
- `AGENTS.md` 只放长期规则和索引，不放具体坑细节；具体条目写入 `docs/pitfalls/`。
- 禁止写入密钥、token、账号密码、隐私数据、生产配置全文或完整敏感日志。
- 历史回填只做一次，后续维护使用增量追加；新增条目必须基于 git 历史、项目文件、当前对话上下文或实际验证结果，不得编造根因、报错、数值或验证方式。

## Release And Global Deployment

- 本项目每次完成 bug 修复、新增功能、删除功能、规则修订、文档修订、部署修复或其他可发布变更后，收尾前必须同步全局 Codex skill。
- 全局同步至少确认 `~/.codex/skills/liran-plan` 和 `~/.codex/skills/plan-docs` 指向本仓库根目录；如更新了斜杠入口口径，也必须同步 `~/.codex/prompts/liran-plan.md`。
- 每次可发布变更默认必须把版本号递增 `0.1`，并在根目录 `README.md` 和相关设计/教程文档写清更新说明；用户在当前任务明确要求版本保持不变时，可作为例外，但仍须完成其它发布门禁。
- 更新说明要说明变更内容、影响范围、使用方式变化、验证方式和遗留风险；涉及流程变化时优先补流程图或表格。
- 新增或修改本发布收口规则本身时，也必须在同一轮立刻按本规则执行一次完整闭环，不能只写规则不跑全局同步、版本更新、提交和推送。
- 收尾前必须运行相关校验；Codex UI / 前端流程相关变更必须运行 `python3 scripts/check_codex_ui_flow_docs.py`。
- 完成后必须提交到 Gitee 并推送当前分支；未成功 commit 和 push 时，不得声称发布完成。
- 不要把无关临时目录、浏览器缓存、测试产物或用户未要求的文件混入发布提交。
