# UI 壳接入清单

> 本文件是项目级 UI 壳总索引。每个独立 UI 壳必须在 `liran_docs/ui-shells/` 下建立单独接入清单；小项目或单壳场景可以先只保留一条索引，但超过 1 个 UI 壳时必须拆分为总索引 + 单壳文件。

## 总规则

- 流程档位：<轻量流程 / 标准流程 / 深度流程 / 完整流程>
- 当前目标：<第 N/M 次 UI 目标>
- UI 路线：<codex / product-design / external-ai / stitch / embedded-model>
- 外部等待：<否 / 等待外部 AI 或 Stitch 结果>
- 任务 ID：<与需求、04、08、09 和归档一致>
- 页面样式检查：<检查页面样式是否符合方案 / 不检查页面样式是否符合方案>
- 验收责任：<Codex 真机测试 / 用户自己测试>
- UI 壳必须严格根据已确认的文本视觉方案，或“文本视觉方案 + 视觉图 / 原型图”创建。
- UI 壳是项目真实前端文件里的外观和交互壳，不是独立 HTML 或 demo。
- 造壳前必须先创建本文件和对应 `liran_docs/ui-shells/<某UI壳>-UI壳接入清单.md`。
- Codex 必须先规划真实前端文件、创建合法占位文件、安排正式入口或临时预览入口、准备 mock/type/局部样式/注释锚点。
- 外部 AI 只允许在 Codex 指定文件里生成 UI 壳，不得自行新增、删除、移动、重命名文件。
- 如果走 `@product-design + $Stitch / Stitch MCP` 路线，Codex 必须先追问 `视觉方案确认好了吗？`，再生成 Stitch 提示词；收到 Project ID / Screen ID 后，先更新本文件和单壳清单，再下载 Stitch 文件并根据 HTML 样式一比一还原到真实前端文件。
- 如果走 `@product-design + $Stitch / Stitch MCP` 路线，必须先根据需求、功能树、模块结构、用户流程和信息架构确认完整页面清单。页面数量不设置固定上限或下限；清单有几个页面就生成几个页面，不得遗漏，也不得自行增加。单次无法完成时可以分批生成，但最终必须覆盖完整页面清单。
- 如果走 `@product-design + $Stitch / Stitch MCP` 路线，真实前端承接必须执行 `实例级尺寸保真规则`：根据 Stitch 原始产物做实例级视觉规格保真的一比一还原，不能把不同按钮、图标、输入控件、表格规格和文本排版行为统一掉。
- 样式默认只能在当前 UI 壳范围内生效，不能污染老页面或全局样式。
- 非 Stitch 路线在 UI 壳接收检查和已触发的 Design QA 通过后，才能解锁后续 development 或 development-and-acceptance 目标接真实接口、状态和业务逻辑。Stitch 路线的初次接收检查通过只能进入强制实例级细节复修；复修通过后才能解锁后续开发目标。
- 本文件只保留当前有效 UI 接线。任务完成时，先把仍有效的视觉、交互、状态和接线规则写回当前模块；一次性外部 AI/Stitch 提示词、接收检查、实例级复修和 Design QA 过程进入单任务归档。
- UI 目标只负责视觉方案、UI 壳、外部 AI/Stitch 承接、高保真复修和适用的 Design QA；真实 API、状态、权限、路由和表单接线必须留给后续开发目标。
- 等待外部 AI 或 Stitch 返回时，暂停并恢复同一次 UI 目标，不得新建 `/goal`、不得增加 N/M。

- [ ] 本文件已生成或更新。
- [ ] 对应 `liran_docs/ui-shells/...md` 已生成或更新。
- [ ] UI 壳需要的文件已由 Codex 创建为合法占位文件。
- [ ] 每个文件用途已写清。
- [ ] 允许外部 AI 编辑的文件白名单已写清。
- [ ] 禁止编辑范围已写清。
- [ ] 查看入口已安排：正式入口或临时预览入口。
- [ ] mock/type/局部样式文件已准备。
- [ ] 代码和单壳清单里已有 `TODO(ui-shell)`、`TODO(codex-connect)`、`TODO(codex-state)`、`TODO(codex-permission)`、`TODO(codex-validate)`、`TODO(codex-route)` 等注释锚点。
- [ ] 外部 AI 提示词已生成，且可直接复制使用。
