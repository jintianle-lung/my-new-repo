## Stitch 落地要求（仅第 4 路线填写）

- Codex 必须根据 Stitch MCP 下载下来的文件里的 HTML 样式一比一还原。
- Codex 必须根据 Stitch 原始产物做实例级视觉规格保真的一比一还原。
- 禁止自由发挥。
- 禁止只模仿大概风格。
- 禁止重新设计。
- 禁止让 Codex 自己凭感觉做。
- 一比一还原对象：HTML 中的 class / style / layout、HTML 里的静态数据、HTML 对应图片和资源、Stitch 输出代码 / MD 规范中能证明样式的内容。
- Stitch 已经生成好了样式，Codex 的任务不是再设计，而是把 Stitch HTML 样式搬到真实前端 UI 壳中。
- 根因口径：常见问题不是大布局没抄到，而是实例级尺寸、间距、图标大小、按钮规格、控件规格、表格规格和文本排版行为被通用化抹平了，或者被老项目默认组件规格、全局样式、公共控件规则带偏了。
- 视觉未对齐前，禁止为了工程整洁、复用、组件化、统一规范而主动做会改变视觉结果的抽象。
- 禁止把不同按钮变体合并成统一按钮组件规格。
- 禁止把不同图标场景合并成统一图标尺寸。
- 禁止把不同输入控件合并成统一规格。
- 禁止把表格筛选栏、表格行高、单元格 padding、操作列按钮和分页控件统一成一套默认规格。
- 禁止先抽象成通用组件，再反过来猜尺寸。
- 样式必须优先局部作用域；高风险控件必须允许实例级覆盖。
- 必须防老项目默认 Button / Input / Icon / Table 规格、全局 `button / input / svg / table` 样式、reset、主题变量和公共类名把 Stitch 结果带偏。
- 如果项目技术栈不能原样表达某种实现，必须说明原因、记录受影响元素，并使用视觉结果等价方案。例外只能是实现路径例外，不能是视觉结果例外。
