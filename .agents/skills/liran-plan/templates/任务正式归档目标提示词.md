## 任务性质

这是独立的正式归档流程，不是普通开发目标，不计入轻量、标准、深度或完整流程的普通目标数量。只有用户已经明确回复“归档”后才允许读取、填写和执行本模板。历史项目补归档使用独立模板，不能与本模板混用。

## 必须读取

读取正式 PRD、需求整理文档、用户原话、项目说明、架构、模块、API、数据、任务拆分、微观任务、04-开发追踪.md、08-测试用例.md、09-真机实测.md、10-UI壳接入清单.md、归档索引，以及适用的 UI、Stitch、外部 AI 和 Design QA 文档。所有路径必须来自真实项目文件，不得猜测。

## 归档前置检查

依次确认：

1. 用户确实明确回复“归档”，并存在真实消息或文件证据。
2. 最后一次普通目标已经完成开发、测试、验收、问题回写和修复复测，并且 goal_status=reclaimed。
3. 没有待确认项、待实测、待用户验收、失败、受阻或未修复问题。
4. 没有新增需求或优化尚未重新整理；UI、Stitch、Design QA 和外部 AI 过程已经完成或有明确不适用记录。
5. 所有相关文件使用同一个任务 ID，正式 PRD 已确认，长期事实具备更新依据。
6. 归档目录不会覆盖其他任务，活动区存在的其他任务不会被影响。

任一前置条件不满足时，立即停止：不创建归档、不更新归档索引、不清理活动区，保留活动区原文，状态写为归档受阻或待处理，并输出真实阻塞原因；不得输出本次任务已完成并归档。

归档失败时原普通目标仍保持 reclaimed，不得重新打开为 active 或修改原普通目标 N/M。归档重试可以复用已保存的用户“归档”确认，但必须保留原确认证据。

## 执行步骤

严格按以下顺序执行：

先更新长期事实。
创建单任务归档。
校验归档内容和证据路径。
更新归档索引。
按任务 ID 清理活动区。
检查其他活动任务未受影响。
检查当前索引有效。
检查活动区无本任务残留。
标记归档状态为已归档。
只有归档成功后才能标记已完成。

归档包必须使用 templates/任务归档.md 的结构，保留原话与确认需求、正式 PRD 及版本、需求变更、需求追踪、任务和微观任务、实施计划、目标说明、开发追踪、测试结果、真机验收和问题回写、Bug 修复与复测、UI/Stitch/外部 AI/Design QA 过程、版本发布资料、长期事实更新、归档索引、安全校验和真实证据路径。

## 失败与保护

归档校验失败、路径不存在、证据不足或任一步顺序不满足时，保留活动区原文，不更新索引，不清理活动区，不标记已归档或已完成。归档只能按当前任务 ID 清理；已取消、暂停归档和被新任务替代不得标记为已完成。

## 完成后输出

只有真实归档、索引更新、按任务 ID 清理、其他任务保护、索引有效和残留检查全部通过后，才输出：本次任务已完成并归档。随后列出真实归档路径、索引更新结果、活动区清理结果、长期事实更新结果和验证命令。
