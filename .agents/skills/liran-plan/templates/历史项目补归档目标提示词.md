8. 检查所有长期有效事实仍然可以从当前文档找到。
9. 检查归档目录没有密钥、token、账号密码、Cookies、浏览器 profile、缓存或隐私日志。
10. 检查没有业务源码、数据库、接口、权限和生产配置改动。
11. 检查没有使用删除命令。
12. 检查未归档成功的内容仍然保留原文。
13. 如果项目有自己的文档校验命令，运行并记录真实结果。
14. 如果两份文件应该保持同步，实际比较内容，不能只凭文件名判断。

十五、完成条件

只有同时满足以下条件才能结束：

- 历史资料已经按任务完成盘点；
- 每个任务都有明确状态；
- 可以安全关闭的任务已经建立独立归档；
- 归档内容和证据路径真实存在；
- 归档索引已经更新；
- 长期有效事实已经保留；
- 活动区只移除了已经成功归档的任务；
- 其他活动任务未受影响；
- 未完成、待验收、失败、受阻和无法确认的任务仍然保留；
- 每个正式完成归档的任务都通过归档合同校验；
- Git diff 没有无关改动和格式错误。

十六、最终输出

最终报告必须列出：

- 目标项目绝对路径；
- 扫描的目录和文件数量；
- 识别出的历史任务总数；
- 正式完成归档的任务及路径；
- 已取消任务及路径；
- 被新任务替代的任务及替代关系；
- 暂停归档任务；
- 仍然活动的任务；
- 归档受阻和无法确认的任务；
- 新增或更新的长期事实；
- 创建的归档索引；
- 移动的独立文件；
- 从混合活动文档中移除的任务段落；
- 清理前和清理后的活动任务 ID；
- 归档合同校验命令与真实结果；
- 项目文档校验结果；
- Git diff 检查结果；
- 是否修改了业务源码；
- 是否存在遗留风险；
- 是否创建提交或推送。

只有归档真实成功时，才能对相应任务写“本次任务已完成并归档”。未完成的任务必须分别写成“仍然活动”“暂停归档”或“归档受阻”，不得用总体完成话术掩盖。
