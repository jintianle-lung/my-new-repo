# 功能一 · 原话留存与关键点续记 SOP

## 目的
先保留用户第一次表达的原话，后续只续记关键点、变更点和确认结果，作为需求溯源的基准。

## 4.4 任务级留存

具体项目修改任务进入需求整理时，不再只把原话追加到一个长期总文件。先按“用户指定 → `AGENTS.md` → `03-索引.md` → 既有同类目录/同任务活动文件”定位目录，再创建或复用 `liran_docs/requirements/<任务ID>-<任务名称>-需求整理.md`（结构模板见 `templates/需求整理工作文档.md`）。首次完整原话只保存一次，后续补充写入同一任务 ID 的需求变更或决策记录；聊天只回执新增、变更和待确认项。

任务验收并安全归档后，原话随单任务归档保存；长期 `用户原话.md` 只保留仍有长期价值的索引或项目级原话，不继续堆积每轮讨论。

## 何时执行
**按档位执行，但不反复搬运同一句原话。** 四档具体修改任务都创建需求整理文档；完整流程才默认创建并持续维护项目级原话总文档。轻量和标准不为一次小改机械新建完整文档树。

## 操作步骤
1. 先判断档位。只有完整流程默认确保目标项目存在 `liran_docs/用户原话.md`；深度、标准和轻量仅在当前档位确实需要且项目已有文档体系时定向更新。
2. 第一次出现的新需求 / 关键决策，保留原话一次。
3. 后续补充时，只追加关键点、变更点、确认结果或待确认项。
4. 按日期分段；同一天多条按顺序排列。
5. 给关键发言加简短括注标签，便于回查，例如：`（修正功能五）`、`（回答 AI 提问·原型形态）`。

## 纪律
- **首次原话不改写、不总结、不润色**——保留错别字和口语，原貌即证据。
- **后续只记关键点**：同主题不要反复搬运同一句原话，重点记录变化和确认结果。
- **区分来源**：AI 自己的查证结论、推断、设计建议**不能**混进用户原话；如确需记录，必须显式标注"（AI 查证结论，非用户原话）"。
- 用户做的**选择题答案**也只需保留一次（连同被选中的选项文字）。

## 关联
- 是功能二需求文档的**上游来源**：需求文档中的每个关键判断，理想情况下能在原话中找到出处。
